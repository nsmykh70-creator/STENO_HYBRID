# STENO HYBRID v8

Экспериментальный блочный lossless-кодек C++17. Формат STN8.

## Что нового

- Быстрый LZ77-парсер: окно 32 КиБ, длина совпадения 4–258 байт, 3-байтовый хеш и один последний кандидат на хеш.
- Поток токенов: `0, literal-byte` либо `1, varint(length), varint(distance)`.
- Предварительная разреженная оценка повторяемости 3-грамм. Если выборка похожа на случайные данные, LZ77-проход пропускается.
- На каждом блоке сравниваются три варианта: RAW, zlib(block), zlib(LZ77_tokens). Выбирается самый короткий полный payload.
- CRC32 на каждый блок, проверка длины, флагов, режима и отсутствия хвостовых байтов.

## Сборка

Требуются g++/clang++ с C++17 и zlib:

```bash
g++ -O3 -DNDEBUG -std=c++17 -Wall -Wextra -pedantic native.cpp -lz -o steno8
```

## Использование

```bash
./steno8 encode input.bin output.stn [level=6] [block=1048576]
./steno8 decode output.stn restored.bin
```

Уровень zlib: 1–9. Размер блока: 4 КиБ–4 МиБ. Декодер определяет формат по сигнатуре STN8.

## Важные ограничения

- Это экспериментальная версия, не рекомендуемая для единственного хранения важных данных без дополнительных проверок и резервной копии.
- В этой реализации обработка файла целиком выполняется в памяти; потоковый ввод/вывод ещё не сделан.
- LZ77 здесь намеренно простой greedy-парсер, не полноценный оптимизированный match finder уровня zstd/LZMA.
- Энтропийный кодер — zlib/DEFLATE. Новизна этапа в обратимом LZ77-токенизаторе, предфильтре и выборе между RAW/DEFLATE/LZ77+DEFLATE, а не в новом энтропийном кодере.
- Результаты ниже получены на синтетических корпусах по 1 МиБ и не доказывают преимущество на произвольных файлах.
