# Дорожная карта STENO_HYBRID

Базовая линия для сравнения — v8 (STN8) и zlib-6 по протоколу из `benchmarks/`.
Метрики: степень сжатия (% от исходника) и скорость ядра кодека (МиБ/с, без файлового I/O)
на 6 реальных файлах и 8 синтетических корпусах по 1 МиБ.

## Волна 1 — v9 (выполнена, ветка v9)

Улучшения LZ-парсера и контейнера. Формат STN9 (несовместим с STN8), бинарник `steno9`.

- [x] Окно 32 КиБ → 256 КиБ, CLI-параметр `window` 4 КиБ–4 МиБ. Главное следствие: длинные
  периоды (period45k в v8 давал 100% — окно 32К и префильтр с шагом 16 не видели период).
- [x] Префиктор повторяемости: шаг выборки 16 → 8 (периоды, кратные 8, теперь обнаруживаются),
  таблица отпечатков 2^20 → 2^22 (ложные срабатывания на случайных данных ~1.5% при пороге 7%).
- [x] Lazy matching (как в gzip): матч в позиции i откладывается, если в i+1 матч длиннее.
- [x] Run-литералы: новый токен `2, varint(n), байты` для серий литералов (одиночные литералы
  остаются токеном `0, байт` — цена одиночек не растёт).
- [x] Максимальная длина матча 258 → 4096 (varint и так её допускал).
- [x] Словарь DEFLATE от хвоста предыдущего блока (последние 32 КиБ исходных байтов;
  deflateSetDictionary/inflateSetDictionary, raw-DEFLATE windowBits=-15, флаг в заголовке блока).
- [x] Полный прогон тестов и бенчей, сравнение с v8 на всех реальных файлах, без регрессий.

## Волна 2 — v10 (выполнена: итерация 1 — скорость, итерация 2 — формат STN10)

- [x] libdeflate: опциональная сборка `-DHAVE_LIBDEFLATE`; словарных блоков в libdeflate нет, поэтому dict-кандидаты по-прежнему через zlib (формат тот же, декодер dispatch по флагу). Энкод ×1.8–1.9, декод ×1.6–1.75.
- [x] Цепочки кандидатов: CLI-параметр depth (1 = байт-в-байт поведение v9; 8 на walk-файлах −0.7% к ratio).
- [x] Rep-коды: кеш последних 4 дистанций (init {1,4,8,16}), rep-токен `3, varint(code)`, code = (length−4)*4 + index. Формат STN10. Период 45000 на реальном файле: 4.76% → 2.05%.
- [x] Словарь token-потока: mode 2, флаг bit1, хвост ≤32 КиБ token-потока предыдущего блока (валидно только если предыдущий блок — mode 2). Формат STN10.
- [x] Потоковый энкод по блокам (std::thread, байты архива идентичны при любом числе потоков).
- [ ] mmap/потоковый I/O — перенесено в волну 3.

## Волна 3 — v11/v12/v13/v14 (выполнена)

(волна 4 — v15: мультифайловый контейнер, см. конец списка ниже)

- [x] Раздельные потоки токенов + rANS order-0 (mode 3): 8 классов, слоты длин/дистанций +
  сырые extra-биты, 32-бит rANS с 12-бит вероятностями. На walk-блоках mode 3 бьёт mode 2
  на ~14% (walk_fine: 19.61% → 16.95% по архиву). Эксперимент показал также, что
  «DEFLATE каждого потока» дал бы ещё ~0.5% — возможное развитие.
- [x] Пресеты `fast` / `default` / `max`.
- [x] Interleaved rANS (4 линии) + массив-декод потоков (v12).
- [x] Оптимальный парсер с ценовой моделью (уровень «max», v12): walk_fine 14.34%,
  fb2 −2.7%, mixed −2.6%, walk_coarse −3.0% к v11.
- [x] Обучаемые словари (v13, STN13): жадный longest-repeat тренер, внешний/встроенный
  словарь, ссылки в словарь из токенов, mode 1 preset; маленькие архивы 150→81 Б (−45%).
- [x] mmap/потоковый I/O (v14): mmap входа (encode+decode), блоки-срезы без копий,
  decode пишет в MAP_SHARED-маппинг выхода, cleanup при ошибке; формат STN13 не менялся,
  архивы идентичны v13. 64 МиБ: приватная память энкод 313→240 МиБ, декод 108→63 МиБ.
- [x] Мультифайловый контейнер STN15 (v15): pack/unpack — один заголовок, один поток
  блоков на все файлы (межфайловые ссылки внутри окна), таблица путей с per-file CRC32,
  traversal-защита; 200/2000 записей: 30.0/300.5 КБ → 9.4/92.5 КБ (−69%, 37% от raw);
  обученный словарь с pack избыточен (перекрывается межфайловыми ссылками).
- [ ] Итеративное уточнение цен DP; векторизация копирования коротких матчей.

## Методика и риски

- Каждая волна: тесты (roundtrip-корпуса, параметры, corruption), синтетический бенч,
  6 реальных файлов, только без регрессий — merge в main и тег.
- Совместимость: STN11 не читается декодерами v8/v9/v10 (осознанно, формат версионируется магией).
- rANS order-0 требует ~512 Б таблицы на блок — для малых блоков невыгоден; order-1 (~128 КиБ)
  рассматривается только для пресета «max».
- База для честной оценки — zstd-3: энкод на скорости zlib-6 при лучшем ratio; добавляется
  в бенч по мере доступности в окружении.
